D.E.X 主题库 · 阿里云终端安装

本包先安装独立主题服务，再接入原 Caddy。不会覆盖盲盒项目、原域名配置或数据库。
要求服务器已有 Docker + Docker Compose v2，并有 curl、ss；通常现有盲盒服务器已具备。

1. 把 dex-themes-server.tar.gz 上传到服务器当前用户的主目录（~/）。

2. 在阿里云服务器终端粘贴这一行：

DEX_STAGE="$(mktemp -d)" && tar -xzf ~/dex-themes-server.tar.gz -C "$DEX_STAGE" && sudo bash "$DEX_STAGE/dex-themes/server/install.sh"

如果终端已经是 root，可去掉 sudo。首次下载 Docker 镜像可能需要数分钟。
脚本将只安装到 /opt/dex-themes，使用独立 dex-themes Compose 项目与持久卷。
它会自动生成两个令牌，保存在 /opt/dex-themes/server/.env，权限 600，不在终端显示。
看到“通过本机健康检查”表示本机服务安装成功；此时公网接口还没有接通。

3. 安装结尾会列出可能的 Caddy 容器及网络，例如：

   dex-caddy-1 | caddy:2 | dex_default

如果你看到的名称正是这两个，执行：

sudo bash /opt/dex-themes/server/connect-caddy.sh dex-caddy-1 dex_default

请用实际显示的容器名和网络名替换示例。不要凭空猜名称。
不确定时，把那几行容器列表发给 D.E.X 开发助手即可；不要发送 .env 或令牌。

4. connect-caddy.sh 会打印：
   - 应插入现有 mydex.top 站点块的短片段；
   - Caddy 配置的主机挂载位置；
   - 对应这个容器的 validate + reload 命令。

先备份对应主机上的 Caddyfile，再把片段插入 mydex.top { ... } 里面。
保留原配置；如果原配置有 route/handle，让 /dex-api/* 路径先于兜底处理。
然后执行脚本打印的 validate + reload 命令。不要停止旧容器，不要覆盖整个 Caddyfile。
若配置路径不是 /etc/caddy/Caddyfile，可把实际容器内路径作为脚本第三个参数。
脚本本身不会修改或重载未知 Caddy 配置，避免影响原盲盒服务。

5. 执行：

curl --fail https://mydex.top/dex-api/health

返回 {"status":"ok",...} 后，在 D.E.X 主题库填写：

https://mydex.top/dex-api

刷新即可连接。上传原创主题时，使用 .env 中 UPLOAD_TOKEN 的值；不要把 ADMIN_TOKEN
分发给普通创作者。首次上传使用新主题 ID；更新现有 ID 需要管理员令牌。
查看令牌仅在你自己的可信终端操作；截图和聊天里请遮盖令牌。

如果 Docker 镜像下载失败
  不会影响原盲盒；先确认服务器可以拉取 node:24-alpine，然后重跑安装命令。
  脚本不自动替换 Docker 镜像源，不调整原服务网络或防火墙。

如果需要回滚
  只移除新增 /dex-api 路由、校验并重载 Caddy，再停止 dex-themes 独立项目。
  不要操作 /opt/DEX 项目的 down，不要删除旧卷。详细方案见 DEPLOY.txt。
