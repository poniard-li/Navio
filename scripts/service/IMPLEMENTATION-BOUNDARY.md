# Navio Windows 后台服务：实现边界与下一步

独立 Windows 后台服务尚未实现。当前公测版通过管理员权限启用 TUN；以下内容记录现有架构与服务方案的实施要求。

## 为什么不能仅包装成一个 SYSTEM 服务

现有 `src/main/core/manager.ts` 直接创建 Mihomo 子进程，并依赖其标准输出、退出事件、PID、看门狗和启动钩子。服务拥有的子进程不属于 Electron；只把权限检查改为“已安装服务”会失去生命周期管理，可能同时运行两个内核。

便携目录和用户配置目录通常可由普通用户修改。若 SYSTEM 服务接受客户端传来的程序路径、命令行、工作目录或未经限制的配置文件，便可能把普通文件修改升级为管理员代码执行或文件读写。固定一个 exe 文件名还不够：内核二进制必须是管理员审核后保存在受保护目录的副本，运行配置、资源路径和控制器接口也要单独处理。

本地 Clash Verge Rev 2.5.10 参考源码已有更完整的服务边界：`src-tauri/src/core/service.rs` 的安装/核心分发路径使用核心文件摘要；运行路径使用 RuntimeBundle、所有者凭据、会话代次与令牌、资源暂存和应用数据所有权检查。其 `Cargo.toml` 固定 `clash_verge_service_ipc` v2.7.7。旧的 `clash-verge-service` 仓库不是可以直接复制后更名的完整当前方案。

## 推荐实施路径

1. 固定审计过的服务与 IPC 源码版本，建立 Navio 自己的服务名、管道名、安装目录和构建产物；不能占用或操控 Clash Verge 已安装的服务。
2. 首次 UAC 安装把经过摘要核验的服务和内核复制到管理员可写目录。安装器固定目标目录、拒绝重解析点，并确认安装所有者 SID。普通客户端不能替换已批准内核；换核/更新按需再次授权。
3. 本地管道限制为指定所有者 SID、SYSTEM 和管理员；从连接对端取得身份，不相信请求正文的用户名。每次核心会话有随机令牌和代次；旧客户端不能停止新会话。
4. 接收有大小和类型上限的运行快照，暂存到服务管理的独立目录。校验资源路径、链接和所有权；不接受任意程序、命令行、PowerShell、`post-up`/`post-down` 或环境变量。
5. 对代理资源、规则资源、GeoData、UI 文件和核心控制器配置重载路径逐项验证安全边界。服务核心控制接口不能成为以高权限读取/写入任意路径的入口。
6. 在 Electron 核心管理器引入明确的本地进程/服务进程生命周期：准备、启动、就绪、日志、停止、崩溃重启、客户端退出、恢复旧状态。普通界面运行；服务失败时先清理，再由用户选择管理员备用方式。

## 发布前必须实际验证

- 独立 Windows 测试机上的首次安装、拒绝 UAC、重启、更新、卸载和修复。
- 普通用户不能替换服务、内核、批准摘要或服务配置；非所有者不能使用管道。
- 恶意路径、重解析点、资源逃逸、超大请求、伪造 SID、旧令牌和断开的客户端均被拒绝。
- 核心退出/服务退出/GUI 崩溃时恢复系统代理和 DNS，避免遗留不可访问网络状态。
- 已有 Clash/Verge/Party 与其他 Windows 用户会话不被接管或终止。
- 稳定/Alpha/Smart 内核各自的受支持范围、配置刷新、资源更新与 TUN 真实流量。

服务发布前需要完成上述实现及独立 Windows 环境验证。
