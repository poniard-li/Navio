Navio — Windows 公测版构建说明

工程来源与构建目标
本工程基于用户提供的 Clash Party 2.0.4 源码进行 Navio 品牌、交互和隔离改造。客户端保留完整功能基座与上游 LICENSE。当前目标是 Windows 公测版，不代表 macOS/Linux 发行版已完成适配和验证。

内核采用固定稳定版 Mihomo v1.19.32，使用已解压便携包中的原样二进制。Navio 没有将该内核宣称为自行开发或修改过的内核；不要把本工程当作 2023 年 CFW clash.exe 的直接替换壳。更换内核版本或文件后需要重新记录来源、校验值并进行兼容性验证。

源码包内容
源码包保留客户端源文件、锁文件、构建脚本、上游 LICENSE 与本说明。
源码包不包含 node_modules、extra、out；它们分别是安装依赖、运行资源和编译结果。

构建准备
1. 在 Windows 上准备 Node.js 24+、pnpm，并将源码包解压到可写目录。
2. 准备 Clash Party 2.0.4 Windows x64 portable 的解压目录。上游发布入口为 https://github.com/mihomo-party-org/clash-party/releases/tag/v2.0.4 。参考包必须含 resources/app.asar、resources/files、resources/sidecar 与 Clash Party.exe。resources/app.asar 的 SHA-256 必须为 801ad4a2dfd770ae4007879d8cf2d5e4f19dbfc92b02703b30b908f846e75abe；内核与原生模块必须匹配 PINNED-RESOURCES.json。仅版本名称相同不足以通过验证。
   官方便携包：https://github.com/mihomo-party-org/clash-party/releases/download/v2.0.4/clash-party-windows-2.0.4-x64-portable.7z
   官方发布记录及 .sha256 文件公布的归档 SHA-256：182063a60b9a06535d176742d627f8b8c95a99aae85fc8752c880efee7da5157（175672213 字节）。本次核对了官方发布记录和校验文件，未重新下载整个上游 7z；解压后仍需通过本项目实际资源校验。
3. 安装锁定依赖，不运行安装生命周期脚本：

   pnpm install --ignore-scripts --frozen-lockfile

4. 将该便携程序的 resources/files 与 resources/sidecar 分别复制到本工程 extra/files 与 extra/sidecar，保留目录结构和资源原内容。
5. 编译客户端：

   pnpm exec electron-vite build

6. 运行固定资源打包脚本；下面三个参数依次是便携程序解压目录、新产物目录、工作暂存目录，均建议使用绝对路径：

   node scripts/package-pinned.cjs "<已解压Party便携目录>" "<新产物目录>" "<工作暂存目录>"

不得将原参考程序目录本身作为新产物目录。以脚本的输入检查和最终执行结果为准；本说明记录构建接口，不以存在脚本代替一次成功构建。

构建边界
此流程重编译 Navio 主进程、preload 和界面，再使用哈希固定的上游 Electron 运行时、运行依赖及原生资源进行重打包，不是把所有第三方组件从源码重建。源码中的 src/native/sysproxy 是 JS/类型封装；实际 Windows 原生 .node 仍来自上述固定参考包。该固定资源目前是可运行发行物构建所需的外部工件，若上游不再提供匹配文件，则不能只凭本客户端源码包复现可运行包，必须另行取得同哈希工件或明确更新并验证构建流程。
所有命令参数由构建者自行指定，不依赖开发者电脑的用户名、目录或服务器密钥。D.E.X 账号服务器、短信/邮件供应商配置、盲盒网站和生产数据不属于此客户端源码包。

固定资源策略
此流程不执行上游 prepare 下载步骤，不自动拉取 latest/alpha 或随时间变化的内核。extra 资源来自上述已解压 resources/{files,sidecar}。不要改用会自动触发下载的上游构建/prepare 命令来替代这里的固定资源流程。需要更新依赖时通过 pnpm 更新锁文件；需要更新内核时另行选择明确版本并保存来源和校验记录。

默认身份与运行设置
• 应用品牌：Navio；协议：dexstudio://。
• 常规用户数据：%APPDATA%\DEX-STUDIO-NEXT；开发运行也不读取 Party 数据。
• 便携数据：程序同级 DEX-STUDIO-NEXT；不复用上游 data 文件夹。
• DEX_USER_DATA 可指定独立验证目录，并优先于常规/便携数据路径。
• 默认混合端口 17890、SOCKS 端口 17891、HTTP 端口 17892。
• 首次启动选择标准/简易模式并保存，完成或跳过引导后不重复自动播放；sysProxy.enable=false、tun.enable=false、allow-lan=false。
• 初始 autoCheckUpdate=true、silentUpdate=false；应用更新与订阅更新是不同设置。

验证注意
DEX_TEST_MODE=1 可跳过托盘、协议注册以及部分启动后台流程，便于隔离预览。代理、TUN 和权限请求本身仍走真实实现，不会伪造成功。
建议 smoke 使用空 DEX_USER_DATA；避免外网自动任务时另设 useSubStore=false、autoUpdateProfileOnStart=false、showTraffic=false。网络信息页保留原有查询行为，仅剔除坐标；隔离测试时按需替换查询目标。
单元测试中的 OS 接口使用 mock；真实订阅、TUN、路由、系统代理与自启动仍需要在明确的目标环境验证。进程清理的定向测试与静态检查仅证明所覆盖的路径，不能作为已消除所有跨客户端影响的保证。公测不等于所有部署场景已验收。

来源与再分发材料请同时阅读 DEX-THIRD-PARTY-NOTICES.txt、LICENSE，以及包内其他组件许可文件。
第三方许可全文与固定版本源代码获取方式见 third-party/。开发者构建依赖由 pnpm-lock.yaml 记录；最终运行包中的运行依赖继承固定参考 app.asar，本流程没有把它们替换为当前开发依赖安装目录。

受限 Windows 测试环境补充
若 electron-vite 的配置打包因上级目录访问受限而失败，可用 Node.js 24+ 运行 node scripts/build-native.mjs；详见 NATIVE-BUILD.txt。此入口不修改权限或依赖，保留原有构建配置和插件。


0.6 公开分发包不附带历史 GeoIP / ASN / GeoSite / BundleMRS 数据。在“外部资源 → 下载最新数据库”中按需获取当前数据，默认从 MetaCubeX 的 GitHub 数据发布下载；这些请求不包含订阅或节点凭据。内核未启动也能下载。依赖缺失数据的规则可能暂时无法启动，网络不可达时需检查资源来源后重试。下载成功后按需重启内核；下载失败不会开启系统代理。原有内核数据更新功能仍保留。
